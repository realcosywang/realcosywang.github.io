使用Hugo和Github Pages搭建免费的静态网站

必备条件

想要快速搭建静态网站，需要简单掌握下面这些基本的技能。

  • 拥有Github账号

  • 安装Git

  • 能够使用terminal

或许你已经开始嫌麻烦要打退堂鼓了，但是请不要害怕，这些技能在网上都有教程，而且很容易上手，本文将不再赘述。有了这些必备条件之后，我们就可以开始着手搭建了。

安装Hugo

对于macOS系统，使用homebrew指令安装hugo

brew install hugo

使用version检验安装完成

hugo version

本文使用的版本是hugo v0.155.0

初始化工程

安装好hugo之后，就可以开始初始化工程了。你希望hugo工程创建在哪个文件夹，使用cd指令跳转到这个文件夹下，接着用下面的命令初始化

hugo new site <your-project-name>

在本文中，<>一律代表需要您手动替换的内容。如果我的项目名称叫my-site，实际运行的指令应该是hugo new site my-site

之后你可以在文件夹中看到这样文件的结构

my-site/
├── archetypes/
│   └── default.md
├── assets/
├── content/
├── data/
├── i18n/
├── layouts/
├── static/
├── themes/
└── hugo.toml

配置主题

你可以在Hugo社区选择你喜欢的主题风格。

我使用的是Anatole，通过社区详情页面找到对应主题的github链接。

我们可以将主题fork到自己的github中，接着使用git submodule的方式进行仓库链接。

本文之后如果没有特别强调，所有指令都在/<your-project-name>路径中执行。

cd  <your-project-name>/
git init
git submodule add <your-github-url>/<your-theme-name> themes/<your-theme-name>

example:
cd my-site
git init
git submodule add https://github.com/realcosywang/anatole themes/anatole

Q：我为什么不直接使用主题仓库，反而要fork到自己的github中？

A：因为之后你对主题进行修改之后，可能会与原主题产生一些冲突，不方便版本管理与后续更新，官方也更推荐将原主题仓库 fork 到自己的账户。

接着在hugo.toml（老版本hugo的配置文件是config.toml）中增加一行配置

theme = "anatole"

现在其实你已经把网站搭建好了，使用指令来启动本地服务

hugo server -D

然后在浏览器中输入：http://localhost:1313/，可以看到带有主题的页面已经出现，现在我们已经成功了第一步🎉，后面将逐步完善页面。

服务在启动状态时，任何对页面的改动都会实时生效，修改后无需重新启动服务。我们先不要按Ctrl+C停止服务，后面还需要增加配置并检查页面。

新建文章

通过下面的指令创建文章

hugo new post/test-post.md

文章会生成在content/post/路径下，这里的post路径不要随便改名，后面会用到。老版本hugo生成的md文件中会有一个字段draft，代表是否为草稿，如果值是false则文章默认不发表，修改成true才可以发表。

现在我们回到浏览器就能看到新建的文章。

关联Github并推送文章

第一步： 创建一个 Github 仓库

  1. 登录后，点击右上角，出现下拉菜单，点击 Your repositories 进入页面
  2. 点击 New
  3. 进入 Creat a new repository 页面
  4. Repository name 这里一定要填 [你的github账号].github.io，像我的帳號是 realcosywang，所以我就要输入 realcosywang.github.io，然后点击 [Create Repository] 。

第二步：执行hugo

hugo

执行后，站点根目录下会生成一个 public 文件夹，该文件下的内容即Hugo生成的整个静态网站。每次更新内容后，将 pubilc目录里所有文件 push到GitHub即可。

第三部：上传代码至 master

首次使用的时候要执行以下命令：

cd public
git init
git remote add origin https://github.com/realcosywang/realcosywang.github.io # 将本地目录链接到远程服务器的代码仓库
git add .
git commit -m "<commit message>"
git push -u origin master

稍等几分钟即可通过我们的自定义域名来访问我们的博客站点了，和我们 hugo server 本地调试完全一致。

第四步：以后每次执行 hugo 命令后，再到public下执行推送命令：

git add .
git commit -m "<commit message>"
git push -u origin master

完善配置

我们可以看到现在页面上，除了刚才创建的一篇文章，剩下几乎是一片空白。现在就来完善配置，丰富页面的内容。

在hugo中，默认只有hugo.toml一个配置文件，但如果把所有配置都放在这里，个人觉得有些杂乱无章，官方也推荐拆分配置，像下面这样

config/
└── _default/
    ├── params.toml
    ├── menus.toml
    └── languages.toml

这里提供创建文件的指令

mkdir -p config/_default && \
touch config/_default/params.toml \
      config/_default/menus.toml \
      config/_default/languages.toml

个人信息

首先，我们来配置个人信息。

先准备一张头像放在static/images/profile.jpg，接着分别配置这几个文件

hugo.toml

baseURL = 'https://example.org/' # 实际域名
theme = 'anatole' # 使用主题

defaultContentLanguage = "zh" # 默认语言
defaultContentLanguageInSubdir = false # 默认语言是否需要在URL中指定路径
hasCJKLanguage = true # 支持计算中日韩语言的阅读时间

[taxonomies]
category = "categories" # 指定文章类别名称
tag = "tags" # 指定文章标签名称

[markup.goldmark.renderer]
unsafe = true

⚠️WARNING

unsafe = true会让Markdown允许HTML，作为个人博客浏览者无法输入信息时不会有任何问题，但如果你的网站支持别人输入HTML，请务必将其设置成false以防止网站被攻击。

params.toml

title = "My name under profile" # 作者名字[1]
author = "author name" # 浏览器标签标题、页脚版权[2]
profilePicture = "images/profile.jpg" # 用户的头像[3]
mainSections = ["post"] # 申明哪些 section 才算“主要内容”，应该被当作文章来展示

languages.toml

[zh]
disabled = false
languageCode = "zh-CN"
languageName = "中文"
weight = 1

[zh.params]
description = "你好，世界" # 个人描述[4]
localizedDates = true
singleDateFormat = "2006年1月2日 15:04"
indexDateFormat = "2006年1月2日"
listDateFormat = "1月2日"

社交平台

Anatole还支持配置社交平台以便浏览者访问，下面以Github为例说明如何配置，如需配置更多平台，请参考这里。

params.toml

[[socialIcons]]
icon = "fa-brands fa-github" # github图标[5]
title = "Github"
url = "<your-github-link>"

[[socialIcons]]
icon = "fas fa-envelope" # 邮箱图标[6]
title = "e-mail"
url = "mailto:mail@example.com"

menus.toml

多语言配置

当我们有多语言的需求时，还需要修改配置。本文将示例支持中文和英文两种语言。

languages.toml

对于这个配置文件，我们只需要按需求配置不同语言的文案即可，示例如下

# 语言级别配置
[zh]
title = "网页标题"
weight = 1
languageName = "中文"
languageCode = "zh-cn"
contentDir = "content/chinese"

[en]
title = "WebsiteTitle"
weight = 2
languageName = "English"
languageCode = "en"
contentDir = "content/english"


# 不同语言的 params 配置
[en.params]
description = "Hello world"
localizedDates = true
singleDateFormat = "Jan 2, 2006 15:04"
indexDateFormat = "Jan 2, 2006"
listDateFormat = "Jan 2"

[zh.params]
description = "你好世界"
localizedDates = true
singleDateFormat = "2006年1月2日 15:04"
indexDateFormat = "2006年1月2日"
listDateFormat = "1月2日"

content

第一步，我们需要根据languages.toml中的contentDir分别去content路径下创建多个语言文件夹，例如

ontent/
└── chinese/
    └── post/
        ├── about.toml
        ├── contact.toml
        └── article-chinese.md
└── english/
    └── post/
        ├── about.toml
        ├── contact.toml
        └── article-english.md

这样，在网站上切换语言时，文章也会自动切换。创作内容的多语言意味着作者需要把每篇文章都翻译成其他语言以供使用不同语言的人阅读。

第二步，修改把参数defaultContentLanguageInSubdir改成true以命中/zh路径。

第三步，在post目录下放一个_index.md，这时hugo 就会为当前路径生成一个index.html列表页，显示该目录下所有文章的列表。没有_index.md的话，有些主题可能不会生成这个列表页。

content/chinese/post/_index.md

---
title: "文章"
---

content/english/post/_index.md

---
title: "POST"
---

我们后续用hugo命令创建文章的时候，若非默认语言，则需要带上全路径，例如

hugo new content/chinese/post/新文章.md

Q&A

Q: 如何设置文章封面

A: 在自动生成的文章参数中添加参数thumbnail: "images/xxx.png"

Q: 首页显示了文章的全部正文

A: 在文章中添加  标记来分隔摘要和正文。

Q: 图片不显示

A: 使用绝对路径 /images/…（开头有 /），图片文件放在 static/images/ 目录下。

Q: 图片太大如何缩小？

A: 使用 HTML 标签：<img src="..." width="500">，或使用
