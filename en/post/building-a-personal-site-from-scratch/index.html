Building a Free Static Site From Scratch

  • Feb 3, 2026 15:18
  • 4-minute read

Building a free static site with Hugo and GitHub Pages

Prerequisites

To quickly set up a static site, you need a basic grasp of the following.

  • A GitHub account

  • Git installed

  • Ability to use the terminal

You might already be thinking it’s too much trouble, but don’t worry—all of this is well documented online and easy to pick up. This article won’t go into those details. With these in place, we can start building.

Installing Hugo

On macOS, install Hugo with Homebrew:

brew install hugo

Verify the installation with version:

hugo version

This article uses hugo v0.155.0.

Initializing the project

After Hugo is installed, initialize a new project. cd into the folder where you want the project, then run:

hugo new site <your-project-name>

In this article, <> means something you should replace. If your project is named my-site, the command would be hugo new site my-site.

You should then see a structure like this:

my-site/
├── archetypes/
│   └── default.md
├── assets/
├── content/
├── data/
├── i18n/
├── layouts/
├── static/
├── themes/
└── hugo.toml

Configuring the theme

Choose a theme you like from the Hugo community.

This guide uses Anatole. Open the theme’s page and find its GitHub link.

You can fork the theme to your own GitHub and add it as a Git submodule.

Unless noted otherwise, all following commands are run from /<your-project-name>.

cd  <your-project-name>/
git init
git submodule add <your-github-url>/<your-theme-name> themes/<your-theme-name>

example:
cd my-site
git init
git submodule add https://github.com/realcosywang/anatole themes/anatole

Q: Why fork the theme instead of using the original repo?

A: After you customize the theme, you may diverge from upstream. A fork keeps your changes under version control and makes updates easier. The docs also recommend forking the theme to your own account.

Add one line to hugo.toml (older Hugo used config.toml):

theme = "anatole"

Your site is set up. Start the local server with:

hugo server -D

Open http://localhost:1313/ in your browser to see the themed site. First step done. Next we’ll refine the content and config.

While the server is running, changes are applied live; you don’t need to restart. Leave it running for the next steps.

Creating a post

Create a new post with:

hugo new post/test-post.md

The file is created under content/post/. Don’t rename the post directory; it’s used by the theme. In older Hugo versions the generated file had a draft field: set it to true to publish, or the post stays draft.

Refresh the browser to see the new post.

Connecting GitHub and publishing

Step 1: Create a GitHub repository

  1. After logging in, click your avatar (top right), then Your repositories in the dropdown.
  2. Click New.
  3. On Create a new repository:
  4. Set Repository name to [your-github-username].github.io. For example, with username realcosywang, use realcosywang.github.io. Then click Create repository.

Step 2: Build the site with Hugo

hugo

This creates a public folder at the project root. Everything inside is your static site. After any update, push the contents of public to GitHub.

Step 3: Push to master (first time)

For the first push, run:

cd public
git init
git remote add origin https://github.com/realcosywang/realcosywang.github.io
git add .
git commit -m "<commit message>"
git push -u origin master

After a few minutes, your site will be available at your GitHub Pages URL, matching what you see with hugo server locally.

Step 4: For later updates, after running hugo, go into public and push:

git add .
git commit -m "<commit message>"
git push -u origin master

Refining configuration

By now the site has one post and is mostly empty. Next we’ll fill in config and content.

Hugo can use a single hugo.toml, but splitting config is cleaner and recommended. Use a structure like:

config/
└── _default/
    ├── params.toml
    ├── menus.toml
    └── languages.toml

Create the files with:

mkdir -p config/_default && \
touch config/_default/params.toml \
      config/_default/menus.toml \
      config/_default/languages.toml

Profile

First, set up your profile.

Put an avatar at static/images/profile.jpg, then configure the following.

hugo.toml

baseURL = 'https://example.org/' # actual domain
theme = 'anatole' # theme in use

defaultContentLanguage = "zh" # default language
defaultContentLanguageInSubdir = false # whether default language appears in URL path
hasCJKLanguage = true # enable CJK reading time

[taxonomies]
category = "categories" # category taxonomy name
tag = "tags" # tag taxonomy name

[markup.goldmark.renderer]
unsafe = true

⚠️ WARNING

unsafe = true allows raw HTML in Markdown. For a read-only blog that’s usually fine. If your site accepts user-supplied HTML, set this to false to reduce XSS risk.

params.toml

title = "My name under profile" # name shown under avatar
author = "author name" # browser tab title, footer copyright
profilePicture = "images/profile.jpg" # avatar path
mainSections = ["post"] # sections treated as main content (posts)

languages.toml

[zh]
disabled = false
languageCode = "zh-CN"
languageName = "中文"
weight = 1

[zh.params]
description = "你好，世界" # profile description
localizedDates = true
singleDateFormat = "2006年1月2日 15:04"
indexDateFormat = "2006年1月2日"
listDateFormat = "1月2日"

Social links

Anatole supports social icons in the sidebar. Example for GitHub; more options are in the theme wiki.

params.toml

[[socialIcons]]
icon = "fa-brands fa-github" # GitHub icon
title = "Github"
url = "<your-github-link>"

[[socialIcons]]
icon = "fas fa-envelope" # email icon
title = "e-mail"
url = "mailto:mail@example.com"

Menus

Configure menu labels in menus.toml. For multiple languages you’ll use separate files like menus.<languageCode>.toml. Example of common items (customize as needed):

menus.toml

[[main]]
name = "首页"
identifier = "home"
weight = 100 # order in menu
url = "/"

[[main]]
name = "文章"
weight = 200
identifier = "post"
url = "/post/"

[[main]]
name = "关于我"
weight = 300
identifier = "about"
url = "/about/"

[[main]]
name = "联系我"
weight = 400
identifier = "contact"
url = "/contact/"

Multi-language setup

For multiple languages, adjust the config. This section shows Chinese and English.

languages.toml

Configure each language and its content directory. Example:

# language-level config
[zh]
title = "网页标题"
weight = 1
languageName = "中文"
languageCode = "zh-cn"
contentDir = "content/chinese"

[en]
title = "WebsiteTitle"
weight = 2
languageName = "English"
languageCode = "en"
contentDir = "content/english"


# params per language
[en.params]
description = "Hello world"
localizedDates = true
singleDateFormat = "Jan 2, 2006 15:04"
indexDateFormat = "Jan 2, 2006"
listDateFormat = "Jan 2"

[zh.params]
description = "你好世界"
localizedDates = true
singleDateFormat = "2006年1月2日 15:04"
indexDateFormat = "2006年1月2日"
listDateFormat = "1月2日"

content

First, create one folder per language under content according to contentDir in languages.toml, for example:

content/
├── chinese/
│   └── post/
│       ├── about.toml
│       ├── contact.toml
│       └── article-chinese.md
└── english/
    └── post/
        ├── about.toml
        ├── contact.toml
        └── article-english.md

Then switching the site language will show the right content. Multi-language content means translating (or adapting) each post per language.

Second, set defaultContentLanguageInSubdir to true so the default language is under /zh (or your default locale path).

Third, add an _index.md under each post directory. Hugo will generate an index.html list page for that section. Without it, some themes won’t show the list.

content/chinese/post/_index.md

---
title: "文章"
---

content/english/post/_index.md

---
title: "POST"
---

When creating posts with hugo new, use the full path for non-default languages, for example:

hugo new content/chinese/post/新文章.md

Q&A

Q: How do I set a post thumbnail?

A: Add to the front matter: thumbnail: "images/xxx.png"

Q: The homepage shows the full post body

A: Add a <!--more--> marker in the post to separate the summary from the rest.

Q: Images don’t show

A: Use an absolute path like /images/... (leading /) and put files under static/images/.

Q: How do I make images smaller?

A: Use an HTML tag: <img src="..." width="500">, or a <figure> for an image with a caption.
